## 🛠 1. Phase 2-A: クロスリファレンス（条文間参照リンク）設計

### 目的
本文中の「前条」「第十条」などの参照表現をパースし、Markdown 相対パスリンク（例: `[前条](./art_001_第一条.md)`）へ変換して、Web ビューワー（SimpleWiki 等）での回遊性を高める。

### ⚠️ 課題と安全対策（Fail-Safe 設計）

1. **誤リンク（デッドリンク）のリスク**:
   - 法令文言には「第三条から第五条まで」「前項第三号に掲げる」「前条第一項」など複雑な範囲指定や準用表現が存在する。
   - すべてをリンク化しようとすると、誤判定やデッドリンクが多発する。

2. **提案アルゴリズム（保守的パターン限定）**:
   - **完全確定できるパターンのみリンク化**:
     - `前条` → 直前の条文ファイル（例: `art_001_第一条.md`）
     - `次条` → 直後の条文ファイル
     - 独立した `第[一二三四五六七八九十百千0-9]+条`（例: `第四条`） → 同一法令内の対応条文ファイル
   - **あいまいな表現はプレーンテキストとして維持**:
     - `〜から〜まで` (範囲指定)
     - `前号`, `前項` (同一ファイル内アンカーリンクは Phase 2 では保留)

## ⚡ 2. Phase 2-B: 複数分類 ZIP の並列一括変換エンジン

### 目的
e-Gov で配布されている 46 個の分類 ZIP（`01_xml.zip` 〜 `46_xml.zip`、全日本法令数千件）を高速に一括処理する CLI コマンドを実装する。

### 仕様案
```bash
# 複数 ZIP が入ったディレクトリを一括バッチ変換
uv run law2md convert-batch ./data/all_zips/ -o ./output_all/ --workers 4
```

- **`multiprocessing` / `concurrent.futures` による並列化**: ZIP ごとにプロセスを割り当て、CPU コアをマルチ活用して高速処理。
- **進捗表示**: `tqdm` 等によるプログレスバー表示。

## 🤖 3. Phase 3: ローカル LLM (Ollama / gemma4) 連携機能

### 目的
変換時にローカル LLM を非同期呼び出しし、Frontmatter にのみ**検索用参考要約 (`reference_summary`)** と **関連タグ (`tags`)** を完全非破壊で付与する。

> [!IMPORTANT]
> **法令本文の完全 ASIS（原本維持）原則**に従い、LLM は Frontmatter のメタデータ生成にのみ使用し、本文テキストには一切手を加えません。

### 技術仕様案

1. **環境設定 (`.env`)**:
   ```env
   LLM_BASE_URL=http://localhost:11434/v1
   LLM_API_KEY=ollama
   LLM_MODEL=gemma4:latest  # または gemma4:e2b
   ```

2. **プロンプト設計**:
   ```json
   {
     "system": "あなたは日本の法令を解析する専門家です。以下の条文本文を読み、検索用の参考要約（1文）と関連キーワードタグ（3個以内）をJSON形式で出力してください。",
     "response_format": {
       "summary": "各事業年度の所得計算および益金損金の原則を定める基本規定。",
       "tags": ["益金損金", "所得計算", "課税標準"]
     }
   }
   ```
