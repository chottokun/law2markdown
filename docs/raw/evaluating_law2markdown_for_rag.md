# **e-Gov法令Markdown変換基盤「law2markdown」のRAG適格性評価と自律的法検索基盤への高度化アーキテクチャ**

## **1\. law2markdownの基本設計とデータパイプライン特性**

日本の行政ポータル（e-Gov）が提供する法令データは、法制執務規則に厳密に準拠した階層構造を保持する標準法令XMLスキーマに基づいて記述されている1。このXML構造は高度な機械可読性を備えているものの、大規模言語モデル（LLM）へのコンテキスト注入や検索拡張生成（RAG）パイプラインへの直接投入においては、冗長な構文マークアップが深刻なトークン肥大化を招くという課題を抱えている1。これに対し、オープンソースプロジェクト「chottokun/law2markdown」は、Python環境上で動作する決定論的CLIパースツールとして、e-Gov法令XMLデータおよび付随する管理CSVをOpen Knowledge Format（OKF v0.2）準拠の構造化Markdownファイル群へと変換する役割を担う1。  
同ツールの基本設計思想は、非決定論的なLLMによる要約やテキスト改変を徹底して排除し、法令原本の条文、文言、句読点に至るまで完全な原本維持（ASIS原則）を貫く点にある1。パース処理においては、漢字の読み分けを規定するルビタグの親文字保存処理、HTMLテーブルを用いた複雑な結合表の再現、LaTeXインライン記法による算式表現の展開など、GitHub-Flavored Markdown（GFM）に準拠した厳密なマッピングが実行される1。  
物理的なファイル配置において、同ツールは単一の巨大な法令文書を生成するのではなく、条文（Article）を最小単位とするファイル分散構造を採用している1。本則条文は独立したファイル群として出力され、附則や別表、様式は別個のサブディレクトリへと明確に分離される1。さらに、同封される管理CSVから法令カナ名、公布日、施行日、改正法令名、未施行フラグといった行政メタデータを自動抽出し、全ファイルの先頭にYAMLフロントマターとして統合する1。加えて、ルートディレクトリから各サブディレクトリに至る全階層に目次インデックスファイルを配置することで、探索時のリンク切れやデッドエンドを防ぐ木構造が自動構築される1。

| 比較項目 | e-Gov 原生法令XML (v3) | law2markdown 変換出力 (OKF v0.2) |
| :---- | :---- | :---- |
| **データ形式** | 階層型XML（深いネスト、属性値依存）1 | GFM準拠 Markdown（YAMLフロントマター付装）1 |
| **分割粒度** | 法令単位（1法典＝1単一巨大XMLファイル）1 | 条文単位（1条文＝1ファイル）＋附則・別表分離1 |
| **メタデータ** | タグ属性および別体管理CSVに分散1 | 各ファイル先頭のYAMLフロントマターへ直接注入1 |
| **数式・表構造** | 専用XMLタグ（TableStruct, ArithFormula）1 | HTML tableタグ、LaTeXインライン記法1 |
| **LLM親和性** | 構文冗長性が極めて高くトークン消費大1 | 純粋テキスト比率が高くMarkdownローダーと即時互換1 |

## **2\. 法令RAGにおける実効的価値と適合性の分析**

law2markdownによって構造化された成果物は、一般的なテキストコーパスを汎用スプリッターで機械的に処理する従来のナイーブRAGと比較して、法令文書の特性に合致した複数の実効的価値を提供する1。  
第一の利点は、規範的境界に整合した自然なチャンキング単位の形成にある。一般的なRAGパイプラインにおいて頻繁に用いられる固定長チャンキングは、法的要件と法的効果の対応関係を途中で分断し、文脈の欠落を引き起こす要因となる8。これに対し、条文単位で物理ファイルを切り出す構造は、法制執務上の論理的自己完結単位である「1条文」をそのままインデックスの最小単位として扱うことを可能にする1。これにより、条文の主文とただし書、あるいは各号に規定された個別要件が同一のコンテキスト内に確実に保持され、検索時における文脈破壊が回避される1。  
第二の利点は、トークン消費の極小化とLLM解釈精度の向上である。生の法令XMLに含まれる無数の構文タグを除去し、純粋な自然言語と最小限のMarkdown記号に圧縮することで、LLMのコンテキストウィンドウの利用効率が飛躍的に改善される1。主要な商用LLMは大量のMarkdown文書を事前学習しているため、見出しやリスト構造として表現された法令構造は意味論的に把握されやすく、構文解析エラーに起因するハルシネーションの抑制に直結する1。  
第三の利点は、決定論的メタデータフィルタリングの即時実行性にある。YAMLフロントマター内に統合された施行日や未施行フラグ、法令番号は、ベクトル検索エンジンにおける高精度な属性フィルタとして直接機能する1。法実務においては、現在施行されている法令のみを探索対象とする要件や、特定の法改正前の規定を遡及して検証する要件が日常的に発生する1。ベクトルの類似度計算を行う前にこれらの属性を用いた決定論的絞り込みを実施することで、時間軸の異なる同一条文の混同を完全に防止できる1。  
第四の利点は、厳密な法的文言の非破壊的保持である。法律の解釈においては、接続助詞の選択や専門的用語の厳密な配置が規範の意味を左右する。要約やパラフレーズを行わないASIS原則の遵守と、ルビタグの親文字保持処理により、形態素解析や埋め込みベクトルの生成過程において語彙境界が破壊されることなく、原典に忠実な検索基盤が担保される1。

## **3\. 法令RAGにおける構造的限界と阻害要因の批判的検証**

上述の有用性を備えている一方で、law2markdownの出力をそのまま標準的なベクトル検索基盤へ投入した場合、大陸法系（シビル・ロー）の法体系構造に起因する深刻な検索失敗と推論の破綻が生じる7。  
最大の問題点は、法典のパンデクテン体系が持つ上位階層コンテキストの剥奪である7。日本の主要法令は、編、章、節、款、目という厳密な包括関係のもとに条文が配置されている1。条文を単一のファイルへ切り離す処理において上位階層の規律スコープ情報がファイル本文から欠落すると、当該条文がどの章の規律下にあるのかをLLMが把握できなくなる1。たとえば、条文内に「前条の規定による」や「この章において」といった相対的参照記述が含まれている場合、孤立したチャンク単体では参照先のスコープを同定することが不可能となり、適用範囲を誤認した回答が生成される7。  
さらに重大な障害は、条文間相互参照および委任・準用規定の切断である7。法令解釈のプロセスは、単一の条文を読み出すだけで完結することは極めて稀であり、原則規定から例外規定、下位政令、施行規則、さらには別法典の準用条文へと遷移する多段階のホップ探索を本質とする7。しかし、生成されたMarkdownファイルは静的なテキストにとどまり、文中に埋め込まれた参照関係を能動的に追跡する機構を有していない1。単一パスの類似度検索のみに依存するシステムでは、参照先の除外規定や政令の具体的要件が検索スコアの上位から漏落し、実務的に完全に破綻した結論を正当な条文引用とともに導き出すという、法令RAG特有の失敗モードが発生する7。  
また、条文単位の固定的な分割は、チャンク粒度の極端な非対称性とベクトル空間の歪みをもたらす8。法令の条文には、極めて簡潔な1文で構成される条文が存在する一方で、十数項にわたり多数の号や複雑な算式、長いただし書が連続する長大な条文も存在する1。長大条文を単一ファイルとして埋め込みベクトルに変換した場合、密ベクトルの情報密度が希釈され、条文内の特定の第〇項第〇号にのみ合致する具体的なクエリに対するコサイン類似度が著しく低下する8。  
加えて、自然言語クエリと抽象的法規範表現との間に存在する語彙の乖離も無視できない8。一般ユーザーが入力する具体的な事実関係の記述と、条文が用いる高度に標準化された抽象概念との間には大きな意味的隔たりがあり、密ベクトル検索単体では適切な条文を引き当てることが困難である8。

| 評価軸 | 単純投入時の実態 | 発生する検索・推論の失敗モード |
| :---- | :---- | :---- |
| **階層的文脈保持** | 上位章節情報の喪失1 | 条文の適用スコープ誤認、総則規定との関係性断絶7 |
| **参照関係走査** | 参照リンクの非解決1 | 例外規定や委任政令の見落としによる誤回答生成7 |
| **チャンク粒度整合** | 条文ごとの極端な長短8 | 長大条文における要件の希釈、個別項号の検索漏れ8 |
| **定義規定連携** | 用語定義の局所的孤立10 | 日常語と法的定義の混同による解釈ハルシネーション10 |

## **4\. 自律的法検索基盤に向けた具体的改良仕様と設計提案**

law2markdownを高度な法的推論を支えるRAG基盤へと進化させるためには、単なる文書フォーマット変換器にとどまらず、法体系の意味論的構造を保持したナレッジグラフ生成基盤へと設計を拡張する必要がある7。

### **階層コンテキストの動的注入仕様**

条文ファイルが単体でベクトル化された場合であっても、その条文が置かれた法体系上の位置付けを消失させない構造を構築する9。XMLパース処理の過程において、ルート要素から当該条文に至るまでの階層木（編・章・節・款・目）を探索・保持し、YAMLフロントマターおよび本文冒頭にパンくずリスト形式の構造メタデータを自動的に挿入する仕様へと改修する1。本文先頭に階層パスを付与することにより、LLMのプロンプト入力時に当該条文が規律する規範スコープが明確化され、章をまたぐ誤解釈が抑止される7。

### **相互参照・委任関係の決定論的抽出とグラフ構造化**

法文内に含まれる形式的な参照表現を正規表現および構文木解析によって網羅的に抽出し、ハイパーリンクおよび関係性メタデータへと変換する9。同一法令内の参照条文は相対パスリンクへと置換し、下位政令や他法令への参照は統一法令識別子を用いたリンク構造へと展開する1。さらに、フロントマター内に出力側参照（参照先条文）および逆引きインデックスに基づく入力側参照（被参照元条文）を配列形式で記述する9。あわせて、参照頻度の高い基本条文については参照先条文の表題や要約文をメタデータフィールドにインライン付加することで、1回の検索で関連条文の文脈を事前結合するアプローチを採用する11。

### **親子階層インデックスに対応したマルチレベル構文出力**

条文単位のファイルを保持しつつ、項（Paragraph）および号（Item）を個別の検索単位として取り出せるデュアル構造を導入する9。具体的には、各項および各号の開始位置に一意の識別子を持つHTMLアンカーおよびセマンティックデータ属性を付与する9。インジェスチョン基盤側において、埋め込み計算は微小な項・号レベルのシャープなテキストで行い、検索ヒット時には親要素である条文全体のコンテキストをLLMへ提供する「ペアレント・ドキュメント・リトリーバル」アーキテクチャを容易に実現できる設計とする9。

### **法令定義レジストリの自動生成**

法令の初期条項に集約される定義規定を構文解析し、法律ごとに用語定義レジストリファイルを自動出力する機構を設ける1。定義条項から抽出された専門用語を索引化し、後続条文内でその定義語が出現した際に構文注釈や用語リンクを配置することで、LLMが一般的な俗用意味と法的な限定意味を取り違えるリスクを根本から排除する10。

| 拡張メタデータ属性 | データ型 | 格納内容とRAGにおける機能 |
| :---- | :---- | :---- |
| hierarchy\_path | 文字列 | 編・章・節・款・目・条の完全階層パス（文脈保持・スコープ制御）9 |
| outbound\_references | 文字列配列 | 当該条文が明示的に参照している条文・政令の識別子リスト9 |
| inbound\_references | 文字列配列 | 当該条文を参照している他の条文・準用規定の識別子リスト9 |
| defined\_terms | 文字列配列 | 当該条文によって法的定義が付与されている専門用語一覧10 |
| child\_anchors | 構造体配列 | 内部に含まれる各項・各号のIDおよび文字オフセット範囲9 |

## **5\. エージェント型法探索基盤への統合と将来展望**

法情報の探索においては、単一の検索クエリで回答を導出するパイプラインから、LLMが思考プロセスに応じて自律的にツールを呼び出すエージェント型アーキテクチャ（Agentic RAG）への移行が進展している7。law2markdownの出力構造は、明確なディレクトリ規約とメタデータ規則を備えているため、探索エージェントに対する外部ツール群のデータソースとして極めて親和性が高い1。  
法令探索エージェントの実装にあたっては、Model Context Protocol（MCP）規格に準拠したツールインターフェースを定義し、法律家が実際に行う思考順序（主要法令の同定、個別条文の照会、上位階層の確認、準用・例外規定の網羅的探索、用語定義の確認）を模倣した関数呼び出し群を提供する7。

| ツール関数名 | 入力パラメータ | 処理内容およびエージェントへの返却データ |
| :---- | :---- | :---- |
| get\_article | 法令識別子, 条番号, 項番号 | 対象条文または項の本文および付帯メタデータを返却1 |
| get\_hierarchy | 法令識別子, 条番号 | 当該条文が属する上位の編・章・節情報および関連条文一覧を返却7 |
| trace\_references | 法令識別子, 条番号, 探索方向 | 参照先条文（例外規定・政令）または被参照条文リストをグラフ走査して返却7 |
| lookup\_term | 法令識別子, 用語名 | 定義規定レジストリから当該用語の厳密な法的定義文を返却10 |

## **6\. 結論**

chottokun/law2markdownは、e-Gov法令XMLに特有の構文的複雑さを排し、原本性を厳密に保持しながらLLM親和性の高いMarkdown群へと決定論的に変換する基盤として高い基礎完成度を備えている1。条文単位のファイル分散とYAMLフロントマターによる管理情報の統合は、ナイーブRAGの構築工数を低減させる有効な出発点となる1。  
一方で、上位章節のコンテキスト喪失、条文間参照の未解決、チャンク粒度の不均一性といった構造的課題が存在するため、単なるテキストファイル群としてのベクトル検索では高精度な法的推論を実現することは困難である7。提案した階層パスの埋め込み、相互参照のグラフエッジ化、項号レベルの親子アンカー構造、定義レジストリの生成、およびMCPツールインターフェースの統合を適用することにより、静的なドキュメント変換器から大陸法体系を自律的に探索可能な次世代の法令ナレッジ基盤へと発展させることが可能となる7。
